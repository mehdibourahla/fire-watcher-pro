# Civil map implementation plan

Approved direction: area-first citizen map using Apple Maps' place/sheet structure, attributed warning details and a synchronized desktop list. Based on the September 16 live-map audit and Mobbin review.

Architecture: retain existing public data contracts and broadcast policy. A pure situation model normalizes satellite fires, official incidents, citizen hazards and ONM warnings for one filtered list/map. Area search works independently of incidents. Open-Meteo remains labelled supporting forecast evidence through the existing weather panel. ITA extraction is currently admin-only and lacks a public publication/geolocation contract: do not expose that private table or fabricate locations as part of a UI change.

Stack: React, TanStack Router/Query, MapLibre, Tailwind, existing i18n and Supabase public queries. No new dependencies, database schema changes or public alert authorization.

- [x] Situation model and tests: shared time/category/area filters; attributed sources; distinguish ended, candidate and unknown states; bounded visible-tab refresh; ONM active validity; no fabricated precision.
- [x] Map primitives and tests: neutral count bubbles, pre-cluster candidate filtering, controlled area centering, warning overlays, load/error fallback, 44px controls, accessible detail focus/return. Preserve other map consumers.
- [x] Citizen page: genuine commune/wilaya search, optional location with denial feedback, synchronized list/map counts, source/freshness strip, hazard chips, URL-backed selection/area/filter, mobile collapsed/expanded sheet and desktop list. Public warning discovery independent of push permission.
- [x] Area weather and follow actions: reuse existing Open-Meteo/ONM evidence panel and subscription controls; preserve official instructions and fire-specific survival behavior.
- [x] Localize AR/FR/EN with existing Kabyle fallback convention; update map metadata. Validate desktop/mobile, RTL, first visit, filters, empty/unavailable, refresh and keyboard.
- [x] Local CI-derived application checks, spec PASS then quality PASS. Feature branch and PR delivery follow; merge/deployment require owner approval.

Acceptance: map/list represent the same filtered geolocated records; unlocated or area-level information stays honestly labelled. Zero records never claims safety. Every record is keyboard-accessible from the list. Expired warnings are not current. Place selection works with no matching records. Query failures retain dated data with visible limitations. URL updates never reset selection inadvertently. Model weather never gains official authority.

## Verification

Local TypeScript, 930 tests across 113 files, production build and diff whitespace checks passed. ESLint has zero errors and 66 warnings (65 existing; one component/helper Fast Refresh warning). CI additionally runs a fresh Supabase migration/test stack and delivery/webhook concurrency tests; no schema, ingestion, publication or delivery policy changed here.

Browser journeys on local QA data passed at 1440×1000 and 390×844: English/Arabic, commune/wilaya search with no incidents, URL/reload persistence, hazard filters, seeded follow picker, selected commune weather, expand/collapse, Help, Escape/focus return and no horizontal overflow. No real subscription or alert was sent. A fresh final page load produced no uncaught page errors.

Browser-only response fixtures verified active/expired/unlocated ONM warnings, ONM details, an unverified road report, matching category counts, and offline retention of loaded data. Fixtures were removed afterward. Candidate fire detail visibility has a caller regression test proven by a failing mutation. Review also corrected delayed map recovery and repeated auto-centering.

Limitations: physical iPhone/Safari and real push permission were not exercised; the mobile sheet expands by button rather than drag. Administrative warning markers are explicitly area centres. Citizen proximity uses 20 km around commune centres, not boundary membership. ONM CAP severity/certainty/urgency values retain the source wording. ITA public publication remains a separate backend contract.

## Overflow correction

The live-map shell now fills the viewport below nonshrinking header/tabs. The toolbar is bounded on short screens; the desktop list and expanded mobile sheet each scroll internally. The collapsed mobile list no longer leaves its contents in document flow, and selecting an item preserves list position and Escape focus return. Other routes retain normal document scrolling and their footer.

Browser measurements matched viewport width/height exactly at 320×568, 390×844, 1024×768 and 1440×900 in English and Arabic. No header controls were clipped at 320 or 1024 px. Mobile list-bottom forecast access and card → details → Escape focus return passed. About retained its footer and 1208 px document at 900 px viewport height. Independent spec and quality rechecks passed.
